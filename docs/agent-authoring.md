# Authoring Cine demos from an agent

Cine accepts project documents, local scene code, media files, and action scripts. Your agent chooses the story and obtains narration from any provider. Cine does not call a model or TTS service. All normal web captures are headless; the bundled Electron app remains hidden. Native capture is an explicit desktop-interacting opt-in and is not needed for this workflow.

## Discover, capture, inspect

```sh
node bin/cine.mjs capabilities --json
node bin/cine.mjs capture --url http://localhost:3000 --script actions.json --work ./capture --json
node bin/cine.mjs author --capture ./capture/meta.json --project ./project.json --json
node bin/cine.mjs inspect --project ./project.json --json
```

`author` creates schema v2 with `camera.policy: "kino"` and `sound.preset: "recorded"`; zoom transition sounds are off. `author --legacy` remains available for v1. Existing saved projects are never regenerated by render. Relative paths resolve from the project file. `inspect` lists resolved scene/layer/audio timings, recorded action milestones, and declared asset paths. Imported module dependencies remain in the scene source. The machine-readable contract is `schemas/project-v2.schema.json`; runtime validation also checks observed milestones, media duration, ordered footage, and cross-references.

Give actions stable IDs in the script. Auto-generated IDs are saved in the capture; discover those through inspection before referring to them. A checked outcome creates a `verified` milestone. A click alone does not prove success. `start`, `dispatched`, `verified`, and `end` are distinct; only applicable milestones exist.

```json
[
  {"id":"open-form","selector":"#open","expect":{"selector":"#form"}},
  {"id":"release-name","type":"type","selector":"#name","text":"September release","typing":{"replace":true,"cps":16}},
  {"id":"save","selector":"#save","expect":{"selector":"#status","text":"Saved"}}
]
```

Typing is animated by default. `typing.mode: "instant"` inserts a whole string. Pacing options are `cps`, `variation`, `punctuationMs`, and `seed`. Complex Unicode graphemes use the browser's insertion path; event metadata identifies it. `type: "key", key: "Backspace"` or a chord such as `key: "Control+A"` / `key: "Meta+A"` sends an explicit key. Text input appends unless `replace: true`. Native physical input currently does not implement replace/key combinations; use the headless Chromium driver for those actions.

Select visible article text with a real browser drag:

```json
{"id":"highlight-idea","type":"selectText","selector":"article p","text":"A sentence to highlight.","dragMs":1100,"dwellMs":2000}
```

The text must exactly match DOM text within the selector (including inline elements); the first match is selected. Cine scrolls the element into view, checks both endpoints, drags with the mouse held down, and verifies the browser selection before recording a `verified` milestone. This supports visible left-to-right prose; split long passages into shorter selections that fit on screen. Avoid starting on links or draggable elements, which browsers may drag instead of selecting. Native capture does not support this action.

Wheel actions scroll smoothly by default over 900 ms with eased acceleration and deceleration. Set `scrollMs` to change the gesture duration; `scrollMs: 0` explicitly requests an instant wheel event. Distances remain pixel deltas, including negative values. An optional `selector` or `point` moves the cursor over a particular scroll area first, preserving the browser's normal wheel handling. Target lookup scrolls offscreen elements smoothly into view and waits for layout to settle; visible targets are not recentered. Browser keyboard shortcuts retain their normal behavior, so use a negative scroll delta for a smooth return toward the top.

```json
{"id":"read-more","type":"scroll","y":480,"scrollMs":1000,"dwellMs":1800}
```

## Scenes and time

A v2 sequence contains `source` footage, `hold` frames, and generated `scene` entries. Each needs a stable ID. Source times are milliseconds inside the original capture. Output times include inserted scenes and footage speed changes.

```json
{
  "schemaVersion":2,
  "capture":"capture/meta.json",
  "output":{"width":1280,"height":720,"fps":30},
  "scenes":[
    {"id":"intro","kind":"scene","entry":"scenes/title.mjs","props":{"head":"A better release"},"durationMs":2400},
    {"id":"workflow","kind":"source","fromMs":0,"toMs":8000,"rate":1},
    {"id":"explanation","kind":"hold","sourceMs":7999,"duration":{"audio":"voice"}},
    {"id":"finish","kind":"source","fromMs":8000,"toMs":12000,"rate":2}
  ],
  "audioClips":[
    {"id":"voice","file":"audio/explanation.mp3","at":{"scene":"explanation"},"role":"narration","captions":{"file":"audio/explanation.vtt"}}
  ],
  "layers":[],
  "camera":{"policy":"kino"},
  "sound":{"preset":"recorded","transitions":false},
  "cover":{"type":"scene","template":"title","props":{"head":"A better release"},"atMs":1000}
}
```

Adjust all source bounds to the real capture. A generated scene inserts time. A `type: "custom"` layer overlays running footage. Hold scenes freeze the selected source frame, camera and cursor; source input events do not replay. Captions and overlays continue advancing.

Placement uses one of `{outputMs:8000}`, `{scene:"explanation",edge:"start",offsetMs:250}`, `{action:"save",event:"verified",offsetMs:250}`, or `{sourceMs:4000}`. Action offsets are output milliseconds after resolving the milestone. References into trimmed footage fail; reattach explicitly rather than guessing a replacement timestamp. Scene durations may depend on decoded audio duration, but not on another scene's duration, avoiding cycles.

## Narration and captions

Place MP3/WAV/M4A files beside the project or use paths relative to it. `trimInMs`/`trimOutMs` select a source-audio interval; `gainDb`, `mute`, `fadeInMs`, and `fadeOutMs` control the clip. Muting a clip also removes its captions and ducking contribution, while preserving its duration. `role` selects narration, effects, or music. Audio duration is measured after decoding. Narration retains its rate and pitch when footage speed changes. To make more room for speech, insert an explicit audio-sized hold or scene. Overflow and accidental narration overlap are validation errors; intentional overlap requires `allowOverlap: true` on both clips.

Caption VTT/SRT or JSON cue times are relative to the untrimmed audio file. A JSON cue has `startMs`, `endMs`, `text`, and optional `words` with the same fields. `captions.wordHighlight` enables highlighting when those word timings exist. `captions.enabled: false` disables burning captions into picture; sidecars still export. `audioClips[].captions.text` is a basic full-clip caption and produces a warning; it does not infer word timings. An MP3 alone supplies neither text nor alignment.

`sound.buses` controls `narration`, `effects`, and `music` via `gainDb`/`mute`. `sound.ducking` has `enabled`, `gainDb`, `attackMs`, and `releaseMs`. The recorded preset uses eight distinct CC0 physical MacBook key samples, a recorded mouse click, deterministic level/sample variation, and a 115 ms minimum typing-sound gap. Zoom transition sounds are opt-in (`transitions: true`). Sound provenance is in `assets/sounds/recorded/`. The earlier subtle synthesized preset remains available for reproducing existing projects. `custom` and `silent` suppress auto-generated cues; mute buses explicitly to silence imported clips. Explicit `audioCues` replace auto-generated cues. The legacy profile and v1 synth remain available for older projects.

## Use, edit, or create scene code

```sh
node bin/cine.mjs scene init --template title --dir ./scenes/title --json
node bin/cine.mjs scene eject --template metric --dir ./scenes/metric --json
```

Both commands create editable files and refuse to overwrite existing source. Templates include `title`, `chapter`, `metric`, and `split`. `metric` and `split` demonstrate React. Reference the returned entry in a scene or custom layer. Agents may edit these files freely or write new entries from scratch. Custom layer example:

```json
{"id":"result-label","type":"custom","entry":"scenes/result.tsx","at":{"action":"save","event":"verified"},"durationMs":1800,"props":{"message":"Saved"}}
```

A browser module exports `createScene(root, context)`, returning `renderFrame(frame)` and optional `dispose()`. A `.tsx`/`.jsx` entry exports a default React component; `adapter: "react"` also selects React for another extension. The adapter owns React mounting/DOM commits. Static `.html` is also supported; it can define `window.createScene` for animation.

Context: `width`, `height`, `fps`, `theme`, `props`, declared `assets`, `seed`, and a seeded `random()` helper for initialization. Frame: `timeMs` within the scene, `outputTimeMs`, `durationMs`, and frame index. Scene dimensions use a logical height of 1080 and matching aspect ratio. Derive animation from frame time and use the provided pure SDK helpers. Do not use wall-clock timers or consume a random stream per frame if you need repeatable seeks. Custom code that violates that contract may render inconsistently.

Declare local assets as `assets: {logo:"assets/logo.svg"}` and use `context.assets.logo`; image/font files become data URLs. HTML can use `{{asset:logo}}`. Module imports and CSS bundle locally; browser-compatible installed dependencies are supported, with pinned React/build tools. Render does not install dependencies or fetch network resources. Scene DOM/styles are isolated in a browser iframe and receive no Node APIs. This is a local authoring environment, not a hosted service for hostile code. Await async asset work inside the scene lifecycle. Build errors and frame failures identify the scene.

## Camera and covers

`camera.policy` is `kino`, `editorial`, `legacy`, or `off`. `kino` uses a pinned copy of Kino’s auto-range generation (300 ms lead, 2500 ms hold, 2500 ms merge gap), all-cursor spatial clustering, edge remapping and exact 1 ms spring integration/post-clamp. `camera.kino` accepts `zoom` (default 1.5), `snapToEdgesRatio` (0.25), `alwaysKeepZoomedIn` (false), and `systemZoom` (1.2). Explicit shots still override automatic policy. The camera algorithm matches Kino at the same input/cadence; Cine retains its own compositor, cursor appearance and scene timeline. Editorial framing uses recorded actions and checked outcomes, with an initial overview; it does not infer arbitrary app semantics. Explicit `camera.shots` override automatic planning. Each shot needs `id`, `mode` (`overview`, `focus`, `hold`, `pull-back`), `at`, and `durationMs`; focus accepts `zoom` and `target: {x,y}` or `{selector}` for a captured anchor. A rectangle `{x,y,w,h}` uses its top-left origin and automatically fits with padding unless `zoom` is explicit. Shots cannot overlap. Numeric `camera.motion` overrides screen/zoom/mouse springs independently; optional scene `camera` overrides affect only that scene. A scene policy override replaces the global automatic/shot policy there; scene shots use the same placement references and output durations. Partial scene motion overrides inherit unspecified project spring values.

Covers support `frame` with `atMs`, `image` with `file` and `fit`, `grid` with `frames`/`columns`, or `scene` with a built-in template or custom entry. A cover-only scene does not alter the movie. Cine exports a separate cover image and metadata; external players may choose their own thumbnails.

## Validate, patch, preview, export

```sh
node bin/cine.mjs validate --project project.json --json
node bin/cine.mjs project patch --project project.json --file changes.json --expected-hash HASH_FROM_INSPECT --json
node bin/cine.mjs preview --project project.json --scene explanation --out explanation-preview.mp4 --json
node bin/cine.mjs render --project project.json --out demo.mp4 --json
```

A patch is an array. Update/remove by ID in `scenes`, `layers`, or `audioClips`; add a full object with an optional insertion index. `set` replaces a top-level cover/settings/camera/sound/captions/output object. Validate before applying; writes are atomic, and an expected hash prevents applying edits over changed content.

```json
[
  {"op":"update","collection":"audioClips","id":"voice","changes":{"gainDb":-4}},
  {"op":"set","path":"cover","value":{"type":"frame","atMs":3500}}
]
```

For a narration hold at a captured event, inspect the event's source timestamp, then use one atomic patch to split the source scene at that time, add a hold with `duration.audio`, and attach the narration to the hold's start. Keep scene IDs stable for unaffected footage.

Preview can instead take `--from-ms` and `--to-ms`. Bounds round outward to the output frame grid, and the artifact manifest records actual bounds. Camera state, scene-local animation, and audio ducking are evaluated against the full timeline before taking the preview. The preview includes a WAV when audio exists. Final exports produce MP4, cover PNG/metadata, caption sidecars when present, and `.artifacts.json`. Audio-only changes reuse a completed silent video from `.cine-cache` when the picture inputs match; changes to captions, footage timing, visuals, or scene code invalidate picture reuse. Inspection exports deliberately render frames again.

`--json` keeps stdout machine-readable; progress goes to stderr. Validation failures return `{ok:false,error:{code,path,message,suggestion}}` when a precise field error is available, or a general error for IO failures. Inspect/validate are read-only. Use `migrate --project old.json --out migrated.json` beside the original to preserve relative paths; migration refuses an existing destination and never modifies its input.
